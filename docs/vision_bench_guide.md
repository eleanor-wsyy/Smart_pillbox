# 视觉台架测试：王姝匀操作版

这轮工具用于先做 B 岗位的采集、标注和计数验证。入口是 `bench_tool.py`，与原来的桌面演示、FastAPI和React APP独立；本轮没有修改硬件固件或APP接口。

**产品目标仍是21格。这里验证的是临时3区域台架，不是21格整机。**

## 1. 安装与启动

### Windows队友首次安装

1. 从GitHub选择 `vision-bench` 分支，再下载ZIP并解压，或克隆该分支。
2. 确保电脑已安装带Tkinter的Python，终端能运行 `python --version`。
3. 双击仓库中的 `setup_bench.cmd`，联网安装三个基础依赖。失败时保留报错，不要直接忽略。
4. 安装完成后双击 `start_bench.cmd`。后续使用不必重新安装。

没有药品或药盒时，打开工具后点 **“软件演练图”**。程序生成已知数量的圆片，并自动标为软件测试夹具；人工数量仍留空，需要自己填写练习。它不能标为真实药片或实拍模拟物，不用于研究报告中的真实药品性能。

希望手动操作时，在仓库文件夹中打开 PowerShell，依次执行：

```powershell
python -m venv .venv-bench
.\.venv-bench\Scripts\python.exe -m pip install -r requirements-bench.txt
.\.venv-bench\Scripts\python.exe bench_tool.py gui
```

已安装过依赖后，只执行第三行即可。也可在 PowerShell 执行 `./start_bench.ps1`。遇到脚本执行策略限制时，使用第三行直接启动，不必更改系统策略。

使用官方Python的Windows发行版（带Tkinter），建议Python 3.10–3.13。OpenCV路径不需要安装Ultralytics、云端SDK或配置密钥。请不要使用无摄像头窗口支持的 `opencv-python-headless` 替换本依赖。

### macOS / Linux手动安装（尚未做真机验证）

```bash
python3 -m venv .venv-bench
.venv-bench/bin/python -m pip install -r requirements-bench.txt
.venv-bench/bin/python bench_tool.py gui
```

Python必须包含Tkinter；Linux发行版还可能需要补齐Tk和OpenCV所需图形系统库。摄像头权限、编号和驱动仍需各自电脑验证。`.cmd` / `.ps1` 是Windows入口，其他系统用上面的Python命令。

工具没有写死本机用户名或输出绝对路径：默认路径从代码目录推导。YOLO权重和云端密钥不随仓库发布，默认OpenCV模式不需要它们。启动工具不会启动APP/API或自动下载检测模型。

## 2. 首次设置（约一个小流程）

1. 固定摄像头和托盘，三个区域内不要放文字、二维码、花纹或反光标签。区域边界尽量画在药格内部，避开隔板。
2. 打开工具，填摄像头编号，按“打开摄像头”。被微信/视频软件占用时先关闭占用程序。没有摄像头可以“打开图片”。
3. 按“拍照/定格”，选择 `Morning/Noon/Evening`，在图上拖动矩形设置区域。三个矩形不能重叠。名字可以改成“测试格1”等。
4. 如果设置镜像或旋转，请重新核对区域。顺序是先旋转、再镜像；原图与变换后的输入图都会保存。
5. “保存配置”保存为 `configs/bench.local.json`。下次“加载配置”即可复用。
6. “检测参数/权重”可修改HSV范围、面积上下界、画面质量阈值或权重路径。配置不包含云端密钥。
7. 开始批次之前先确认区域。“开始新批次”会锁定参数和区域；要调参，先结束批次，再开始新批次。

默认OpenCV配置针对**浅色目标+哑光深色托盘**，是HSV轮廓基线。对颜色接近背景、接触和重叠的药片可能漏计或合并，并不代表已训练药丸识别模型。所有格子使用相同的HSV范围，不把早中晚格子绑定到红绿蓝药片。

## 3. 每条数据如何采集

1. 先用模拟物跑通操作，再由团队确认适当的真实药片测试样本；真实药片和模拟物分别标注，不在测试中进行服药操作。
2. 重新摆放样本，继续预览，再按“拍照/定格”。每张新画面会清空人工数量，防止沿用上一条标签。
3. 人工数一遍每格实际数量。**0表示确认空格；空白表示未标注。**不要照抄模型预测。
4. 填写样本类型、阶段、光照、背景、角度、重叠、遮挡、设备型号及备注。右侧表单可用滚动条向下查看；检测和导出按钮固定在右下方。
5. 看不到数量或画面不可用时，在“画面质量”选择遮挡、反光等原因。记录仍保存，但预测为空，不当作0。
6. 按“检测并保存样本”，等待结果。图像和记录保存在当前批次目录。
7. 下一条重新摆放和拍摄。同一张定格画面不能重复保存。固定场景连拍也不能当成多个独立场景。
8. 完成后按“导出当前批次”。也可以以后使用“导出已有批次”重算。

后台质量检查仅是区域亮度、过曝比例、可选清晰度阈值和OpenCV颜色掩膜占比检查。它不能自动可靠识别所有手部遮挡、药片重叠、摄像头偏移或断线后的旧画面，必须人工查看。默认清晰度阈值为0（关闭），避免尚未标定的阈值把空格误判为失焦。

标注错误时不要直接改原始JSON再假装原记录正确。把该批次注明为探索/误标批次，重新采集用于正式评估；当前版本不提供带审计的事后改标工具。

## 4. 结果目录与统计口径

```text
runs/bench/批次ID/
  manifest.json                 配置快照、模型身份、版本、代码/权重哈希
  samples/样本ID/
    raw.png                     采集/导入的原图
    input.png                   实际检测图（旋转/镜像后的输入）
    overlay.png                 区域与预测轮廓/检测框
    sample.json                 逐格记录，原始预测与人工数量分列
  exports/
    records.csv                 所有记录，UTF-8 BOM，可用Excel打开
    metrics.csv                 分组指标
    metrics.json                指标及统计口径
    failures.csv                数量不符、无法判断及错误记录
    failures.html               本地失败样本图册，双击打开
```

导出前校验原图/输入图哈希以及配置标识；完整批次目录需要一起保留，不要只拷贝CSV或移动其内部图片。哈希用于发现图片误改，不是防篡改签名；原始人工标注仍需团队核对。

统计单位为**一张图片中的一个人工标注格子**，不是患者人数、服药次数或独立临床样本。同图的三个格子不是三个独立采集场景。

- `exact_rate_all_labelled`：完全匹配数/全部已标注格子，失败计入分母。
- `coverage`：有效预测数/全部已标注格子。
- `exact_rate_valid_only`、`mae_valid_only`：只在有效预测中统计，应与覆盖率同时展示。
- 未标注不计算准确率；无数据为null/空白，不输出0%或100%的假结果。
- 真实药片、模拟物、软件测试夹具、调参、正式评估、摄像头和图片来源分别统计。不计算混合总准确率。
- `confidence`为模型输出或OpenCV掩膜工程分数，不能用作实测准确率。
- 没有EMA平滑和服药状态机；`smoothed_prediction`、`event`留空。
- 数量下降不证明服药/吞咽，本轮不评估服药依从性。

时间采用带UTC时区的ISO格式。摄像头记录当前读帧时间；导入图片记录本次导入时间，不推测拍摄日期，必要时另在备注保留来源时间。

## 5. 首轮测试清单

先调参，再固定摄像头、区域、背景和检测参数做单独评估。建议首轮从以下场景开始，每种独立重新摆放拍摄5次；这只是小样本工程初测，不能推出真实居家总体准确率。

| 场景 | 人工标签 | 要观察什么 |
|---|---|---|
| 三格均为空 | 0/0/0 | 是否产生背景误检 |
| 数量组合 | 2/1/3，并变换位置 | 基础计数与位置变化 |
| 多种单独数量 | 0–5粒，按格标注 | 数量上升是否影响漏检 |
| 色彩/外观变化 | 按实际数量 | 模型是否只适用某种样本 |
| 接触与部分重叠 | 按实际数量，标记重叠 | 轮廓合并与漏计 |
| 较暗、较亮、侧光 | 按实际数量 | 质量拒绝与计数错误 |
| 浅色背景/反光背景 | 按实际数量 | 背景误检/无法判断 |
| 手遮挡或区域偏移 | 不清楚则留空，人工标记不可用 | 不输出假0，不生成取药事件 |
| 断开摄像头 | 无有效新图 | 提示读取失败，不切模拟器 |

调参用的摆放与图片不要再标为正式评估样本。先决定每个条件拍多少次，再完整记录，不删除失败样本只保留好看的数字。

## 6. 离线命令（算法同学可用）

每次 `record` 新建一个冻结配置的批次；要在同一批次采集多张，使用GUI。

```powershell
# 生成空白表，文件存在时拒绝覆盖
python bench_tool.py template --output runs/实验记录空表.csv

# 导入原始图片；counts顺序与配置slots顺序一致
python bench_tool.py record --config configs/bench.local.json --image D:/测试/原图.png --counts 2,1,3 --kind simulant --phase tuning --lighting 室内光 --background 深色托盘 --device 笔记本摄像头

# 未标注样本：省略counts；部分未标注可用 --counts "2,,3"
# 明显遮挡：增加 --invalid 手部遮挡
# kind只能为 real_pill / simulant / test_fixture
# phase只能为 tuning / evaluation

# 重算已有批次（替换为实际目录）
python bench_tool.py export --batch runs/bench/实际批次ID

# 软件测试，不需要摄像头或密钥
python -m unittest discover -s tests -v
```

记录中有推理失败/无法判断时，命令仍保留样本并导出，退出码为2。没有有效输入时不制造空药格记录。成功退出码为0。

重新检测历史批次时使用其中 `raw.png` 及原配置，不要把已经旋转/镜像的 `input.png` 当成原图再次变换。重新检测属于新批次，并在备注说明复用图像，不能算新增独立样本。

## 7. 可选YOLO与Roboflow

**本地YOLO**：另外安装 `ultralytics`，在参数中设置 `backend=yolo` 与专用药丸权重的绝对路径。没有权重或类别不匹配时明确失败，不下载通用COCO模型。当前适配器复用原仓库的YOLO推理入口；真实权重尚需团队提供并验证。

**Roboflow**：在启动GUI的PowerShell中设置环境变量：

```powershell
$env:ROBOFLOW_API_KEY="你的密钥"
python bench_tool.py gui
```

在参数中选择 `backend=roboflow`、模型 `project/version`。GUI会确认上传；CLI选择云端配置并执行record即授权这一张图上传。云端接口使用Roboflow的base64图片POST接口，JPEG编码发送同一冻结画面，不缓存上一张预测。默认超时20秒。服务失败、响应无效或密钥缺失不会回退OpenCV。

不要拍摄面部、病历、姓名或其他个人信息。不要将真实密钥写进配置、截图或仓库。云端模型版本号可记录，但不能保证服务方永远不更新底层模型，因此严谨评估优先使用有权重哈希的本地模型。

**本轮没有真实摄像头、专用YOLO权重、Roboflow在线推理或最终药盒验证结果。**软件测试和夹具演示不能写成真实药片准确率。硬件完成后还要重新标定区域、光照和拍摄位置，另做整机验证。
