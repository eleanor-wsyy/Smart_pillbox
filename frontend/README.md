# Smart Pillbox 前端 · 家庭照看

基于 React + Vite + TypeScript 的单机演示界面。设备状态与设备事件读取 FastAPI；家庭成员、交接单、人工确认的用药计划、库存和装药记录（含压缩后的照片）保存在**当前浏览器**的 localStorage。首次进入不预置病例、服药记录或家属。

## 本地启动（正式演示：main 分支）

在 Windows PowerShell 中，从仓库根目录启动后端（建议 Python 3.10+）：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn api_server:app --host 127.0.0.1 --port 8000
```

另开终端，进入 `frontend`（建议 Node.js 22；首次安装需要联网）：

```powershell
cd frontend
npm ci
npm run dev
```

打开 http://127.0.0.1:5173/ 。验证构建运行 `npm run build`。`npm ci` 会严格使用仓库提交的 `package-lock.json`；不要在新机器手工补依赖。若改用 pnpm，在干净目录运行 `pnpm install --frozen-lockfile`、`pnpm dev`、`pnpm build`，不要与 npm 混装。`pnpm-workspace.yaml` 不再限定 Linux-only 架构，原生可选包按当前系统安装。Linux/macOS 后端使用 `python3 -m venv .venv`、`.venv/bin/python -m pip` 和 `.venv/bin/python -m uvicorn`。

`vite.config.ts` 将 `/api` 代理到本机 8000。生产部署可设置 `VITE_API_BASE`。家庭圈等本地数据保存在当前浏览器，不跨设备同步；浏览器端中文 OCR 首次识别需联网下载语言包。

## 功能与安全边界

- 首页/药盒：从 `/api/status` 显示药格数量；提醒从 `/api/events` 获取 `warning`/`critical` 事件；历史合并后端事件与本地真实操作，并按类型筛选。断线显示错误，不回填假状态。
- 家庭圈：添加一位主照顾人和临时照顾人、生成用药计划/药格状态/库存提醒快照、由选中的接手人确认、结束交接，均留时间戳和本机事件。**身份选择不等于真实身份验证**。
- 病历照片：使用浏览器内 tesseract.js 的 `chi_sim+eng` OCR 转写原文；真实识别失败时明确提示改为对照图片手工录入。**OCR 文本不会直接生成生效的处方**，家属逐项填写药名、频次、剂量、时段和数量后点击人工确认。照片仅当前页面临时预览，不上传或永久保存；不要上传未获授权的敏感资料。首次识别语言包需联网。
- 人工确认计划的药格**数量**经新增 `POST /api/medplan` 同步后端（每格 0–3 粒）；`POST /api/period` 原接口只负责切换当前时段，未修改其行为。离线确认暂存本机，恢复后需点击“同步数量到设备”。后端重启后计划数量会恢复为模拟器默认值，也需重新同步。
- 装药记录：装好后选择本次装好的早/中/晚药格（可以只选一格），拍或选一张照片，再保存。记录人从当前已确认交接的照看人或主照顾人带入，保存时间自动生成，同时记下所选药格的计划摘要和设备数量；不再要求逐格拍照、选批次或填写其他复核字段。无已确认计划、设备离线、计划数量未同步、数量不符、识别不稳定或对应未处理过期库存时不能保存。照片压缩后与最近 8 条记录留在当前浏览器，旧记录仍可查看但旧版只存文件名。
- 保质期：家属录入库存数量与有效期；距有效期不超过 30 天高亮；过期/临期可标记已处理并记录。本地设备不能检测药品有效期，依赖人工录入的包装日期。

**取药事件 ≠ 服药/吞咽确认。** 单摄像头与数量变化不能证明老人已经吞咽，界面和记录只称“取药”或“装药记录”，不称“已服用”。设备页的 0–3 粒按钮、取空及重置真实调用现有模拟接口，不会产生虚构的服药历史。

## 验收与已知限制

- 历史截图：`docs/screenshots/` 是此前逐格复核版本的验收留档，不代表当前装药页面。
- 自测步骤与结果：见 `docs/acceptance.md`。
- 后端 `/api/events` 只保留最近 50 条并在重启后丢失；本地事件最多 300 条、仅本机可见，不提供云同步、多端一致性、真实推送、身份认证或医疗决策能力。
- OCR 仅负责文字转写，无法医学地识别处方；装药照片仅供人工回看，系统无法识别药品身份、批次或操作者真实身份，也不能由总数量推断混格药品的品种。此功能是留痕与数量异常提醒，不是临床意义上的自动复核或服药证明。照片没有云端备份，清除浏览器数据或换设备会丢失，勿将其作为唯一医疗记录。
- demo 中的设备画面为**模拟器数据**，没有真实摄像头视频，也不代表临床器械验证。通知设置和虚构联系人被移除，避免展示未接入的能力。
